## Overview

This evaluation framework computes two main types of metrics:

- **Accuracy**: Whether the final answer is correct
- **Match F1**: Quality of the reasoning process (step-by-step)

Both metrics are important for evaluating multi-modal reasoning models.

---

## Accuracy Metrics

### Overall Accuracy

```
Accuracy = (Number of Correct Answers) / (Total Questions)
```

**What it measures:** How often the model produces the correct final answer.

**Range:** 0.0 to 1.0 (0% to 100%)

**Interpretation:**
- `> 0.90`: Excellent performance
- `0.70-0.90`: Good performance
- `0.50-0.70`: Moderate performance
- `< 0.50`: Poor performance

### Confidence

```
Confidence = Model's certainty in the accuracy evaluation
```

**What it measures:** How confident the system is that the predicted answer matches the ground truth.

**Range:** 0.0 to 1.0

**Values by match type:**
- `1.0`: Exact match (e.g., "A" = "A")
- `0.9-0.95`: Numeric match with tolerance (e.g., 0.67 ≈ 0.67234)
- `0.7-0.9`: LLM-verified semantic match (e.g., "Paris" ≈ "The capital is Paris")
- `0.3-0.7`: Partial/substring match
- `0.0`: No match or placeholder

**Why confidence varies:**
- Exact matches have high confidence (1.0)
- Rounded numbers have slightly lower confidence (0.9-0.95)
- Paraphrased answers have variable confidence (0.7-0.9)
- Incorrect answers have low confidence (0.0-0.3)

**Average Confidence interpretation:**
- `> 0.90`: Most answers are exact matches
- `0.70-0.90`: Mix of exact and approximate matches
- `0.50-0.70`: Many approximate or partial matches
- `< 0.50`: High proportion of incorrect or uncertain matches

### Match Type

Categories of how answers were matched:

- **`exact`**: Perfect text match after normalization
- **`choice`**: Multiple choice (A, B, C, D) extraction
- **`numeric`**: Number comparison with tolerance
- **`yes_no`**: Boolean question matching
- **`llm_verified`**: Semantic similarity via LLM judge
- **`placeholder`**: No prediction available

## Match F1 Metrics

Measures the quality of reasoning steps by comparing predicted steps to reference steps.

### Match F1

```
Match F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**What it measures:** Balance between precision and recall in step matching.

**Range:** 0.0 to 1.0

**Interpretation:**
- `> 0.80`: Excellent reasoning alignment
- `0.60-0.80`: Good reasoning alignment
- `0.40-0.60`: Moderate reasoning alignment
- `0.20-0.40`: Poor reasoning alignment
- `< 0.20`: Very poor or missing reasoning

### Precision

```
Precision = (Matched Predicted Steps) / (Total Predicted Steps)
```

**What it measures:** What fraction of the model's predicted steps are relevant/correct.

**High Precision (>0.8):** Model generates few but accurate steps
**Low Precision (<0.4):** Model generates many irrelevant or incorrect steps

**Example:**
```
Reference steps: [A, B, C]
Predicted steps: [A, B, D, E]

Matched: A, B (2 steps)
Precision = 2/4 = 0.50
```

### Recall

```
Recall = (Matched Reference Steps) / (Total Reference Steps)
```

**What it measures:** What fraction of the reference steps are covered by predictions.

**High Recall (>0.8):** Model covers most important reasoning steps
**Low Recall (<0.4):** Model misses many important reasoning steps

**Example:**
```
Reference steps: [A, B, C, D]
Predicted steps: [A, B]

Matched: A, B (2 steps)
Recall = 2/4 = 0.50
```

### Precision vs Recall Trade-off

**Precision > Recall:**
- Model generates **few but accurate** steps
- Missing some important reasoning
- **Action:** Encourage more comprehensive reasoning

**Recall > Precision:**
- Model generates **many steps** but some are irrelevant
- Verbose or redundant reasoning
- **Action:** Encourage concise, focused reasoning

**Balanced (P ≈ R):**
- Model generates **appropriate number** of relevant steps
- **Ideal scenario**

### Step Matching Details

**num_predicted_steps:** Number of reasoning steps generated by the model

**num_reference_steps:** Number of ground truth reasoning steps

**num_matched_predictions:** How many predicted steps matched references

**num_matched_references:** How many reference steps were matched

**avg_similarity:** Average semantic similarity between all step pairs

**max_similarity:** Maximum similarity found between any step pair

**threshold_used:** Similarity threshold for considering a match (typically 0.35-0.45)

## Understanding High Standard Deviation

### What is Standard Deviation (Std)?

```
Std = √(Σ(xi - μ)² / N)
```

Measures how spread out the values are from the mean.

### Why High Std Occurs

**Example:**
```
Match F1: 0.5280 ± 0.2584  (std = 0.2584)
```

**Coefficient of Variation (CV):**
```
CV = (Std / Mean) × 100 = (0.2584 / 0.5280) × 100 = 48.9%
```

**Interpretation:**
- **CV < 25%**: Low variance (consistent performance)
- **CV 25-40%**: Moderate variance (some inconsistency)
- **CV > 40%**: High variance (inconsistent performance) ← YOUR CASE

### Reasons for High Std

#### 1. **Task Diversity** (Not a bug - it's a feature!)

VQA reasoning tasks contain questions of varying complexity:

```
Easy questions (F1 ≈ 0.8-0.9):
  "How many red objects are in the image?"
  → 2-3 simple reasoning steps

Hard questions (F1 ≈ 0.2-0.3):
  "Based on the spatial relationships and historical context,
   infer which action would logically occur next..."
  → 8-12 complex reasoning steps
```

**This is EXPECTED and NORMAL for diverse datasets.**

#### 2. **Model Inconsistency**

Model performs well on some question types but poorly on others:
- Good at counting, poor at causal inference
- Good at spatial reasoning, poor at temporal reasoning

#### 3. **Placeholders**

Missing predictions (F1 = 0.0) lower the mean and increase variance.

#### 4. **Reference Step Count Variation**

Some questions require 2 steps, others require 15+ steps.

### Is High Std Bad?

**NO - if it reflects genuine task diversity!**

**In academic papers:**
- High std is ACCEPTABLE if explained properly
- All models in the field have similar std
- Shows your dataset is challenging and diverse

**In papers, report:**
```latex
Match F1: 0.528 ± 0.258 (median: 0.557, IQR: [0.342, 0.723])
```

**And explain:**
> "The standard deviation reflects the inherent diversity of our dataset,
> which includes both simple perception tasks (F1 ≈ 0.8) and complex
> multi-step reasoning (F1 ≈ 0.3). This variance is consistent with
> prior work on visual reasoning tasks [citations]."

## Question Difficulty

### How to Identify Difficulty

**Method 1: Empirical (Data-Driven) - RECOMMENDED**

Use actual model performance to classify:

```python
# Based on Match F1 percentiles
Easy:      F1 >= Q3 (75th percentile)
Medium:    Q2 <= F1 < Q3
Hard:      Q1 <= F1 < Q2
Very Hard: F1 < Q1 (25th percentile)
```

**Advantages:**
- ✅ Based on real data
- ✅ No additional model bias
- ✅ Reflects actual difficulty

**Disadvantages:**
- ⚠️ Model-specific (what's easy for GPT-4 may be hard for smaller models)

---

**Method 2: Feature-Based (Model-Independent) - UNBIASED**

Analyze dataset characteristics WITHOUT using model predictions:

**Complexity Indicators:**

1. **Reference Step Count**
   - More steps = more complex reasoning
   ```
   Simple: 2-4 steps
   Complex: 8+ steps
   ```

2. **Question Length**
   - Longer questions often require more reasoning
   ```
   Simple: < 200 characters
   Complex: > 400 characters
   ```

3. **Question Type**
   - Counting: Easy
   - Spatial relationships: Medium
   - Causal inference: Hard
   - Multi-step conditional reasoning: Very Hard

4. **Answer Type**
   - Multiple choice (A/B/C/D): Usually easier
   - Numeric: Medium
   - Free-form text: Harder

5. **Linguistic Complexity**
   - Word count
   - Sentence structure complexity
   - Use of conditional/causal connectives ("if", "because", "therefore")

### Detecting Complex Questions (Without Model Bias)

**Script: `analyze_dataset_complexity.py`**

Analyzes dataset features to assign complexity scores based on:
- ✅ Reference step count (from ground truth)
- ✅ Question length and structure
- ✅ Linguistic features
- ✅ Answer type
- ❌ NO model predictions (unbiased!)

---

#### How the Complexity Score is Calculated

The complexity score (0-1 scale) is computed using a weighted combination of multiple features:

**1. Normalized Feature Scores (0-1 range):**

```python
# Step count complexity (40% weight)
step_complexity = min(num_reference_steps / 20.0, 1.0)

# Length complexity (20% weight)
length_complexity = min(question_length / 1000.0, 1.0)
word_complexity = min(question_words / 150.0, 1.0)
avg_length_score = (length_complexity + word_complexity) / 2

# Linguistic features (20% weight)
linguistic_score = sum([
    0.15 if has_conditional else 0.0,  # "if", "when", "unless"
    0.15 if has_causal else 0.0,       # "because", "therefore"
    0.10 if has_comparison else 0.0,   # "more", "less", "than"
    0.10 if has_negation else 0.0      # "not", "no", "never"
])

# Question type modifiers (20% weight)
type_score = sum([
    -0.15 if is_counting else 0.0,     # Counting questions are easier
    -0.10 if is_yes_no else 0.0,       # Yes/No questions are easier
    +0.20 if is_why else 0.0,          # "Why" questions are harder
    +0.15 if is_how else 0.0,          # "How" questions are harder
    +0.25 if is_what_if else 0.0,      # Hypothetical questions hardest
    -0.10 if is_multiple_choice else 0.0,  # MC is easier
    -0.05 if is_numeric else 0.0,      # Numeric answers easier
    +0.10 if is_free_text else 0.0,    # Free text is harder
    +0.10 if num_sentences > 1 else 0.0  # Multi-sentence harder
])
```

**2. Weighted Final Score:**

```python
complexity_score = (
    0.40 * step_complexity +        # 40% weight on reference steps
    0.20 * avg_length_score +       # 20% weight on question length
    0.20 * linguistic_score +       # 20% weight on linguistic features
    0.20 * type_score               # 20% weight on question type
)

# Clip to valid range [0, 1]
complexity_score = clip(complexity_score, 0.0, 1.0)
```

**3. Classification into Levels:**

```python
if complexity_score >= 0.7:
    level = "very_hard"    # Top 0.02% of questions
elif complexity_score >= 0.5:
    level = "hard"         # Challenging questions (1.5%)
elif complexity_score >= 0.3:
    level = "medium"       # Moderate difficulty (37.3%)
else:
    level = "easy"         # Simple questions (61.2%)
```

---

#### Feature Detection Details

**Linguistic Complexity Patterns:**

```python
# Conditionals - indicate logical reasoning
conditionals = r'\b(if|when|unless|provided|given that)\b'

# Causals - indicate causal reasoning
causals = r'\b(because|since|therefore|thus|consequently|as a result)\b'

# Comparisons - indicate comparative reasoning
comparisons = r'\b(more|less|than|compared to|relative to)\b'

# Negations - add cognitive load
negations = r'\b(not|no|never|neither|without)\b'
```

**Question Type Detection:**

```python
# Counting questions (usually easier)
is_counting = bool(re.search(r'\b(how many|count|number of)\b', question, re.I))

# Yes/No questions (easier, binary answer)
is_yes_no = bool(re.search(r'\b(is there|are there|does|do|can|will)\b', question, re.I)
                 and question.strip().endswith('?'))

# Why questions (harder, require explanation)
is_why = bool(re.search(r'\b(why|explain|reason)\b', question, re.I))

# How questions (harder, require process description)
is_how = bool(re.search(r'\b(how|in what way)\b', question, re.I))

# Hypothetical questions (hardest)
is_what_if = bool(re.search(r'\b(what if|suppose|imagine)\b', question, re.I))
```

**Answer Type Classification:**

```python
# Multiple choice (A/B/C/D) - easier to verify
is_multiple_choice = bool(re.match(r'^[A-D]$', answer.strip()))

# Numeric answer - medium difficulty
is_numeric = bool(re.match(r'^\d+\.?\d*$', answer.strip()))

# Free text - hardest to verify
is_free_text = not is_multiple_choice and not is_numeric
```

**Advantages:**

1. Assumes reference step count is accurate
2. May not capture semantic complexity perfectly
3. Simple heuristics for linguistic features
4. Fixed weights (not learned from data)

import json
import pandas as pd

# Load complexity scores
with open('dataset_complexity_scores.json') as f:

complexity_map = {
    s['sample_idx']: {
        'complexity_score': s['complexity_score'],
        'complexity_level': s['complexity_level'],
        'num_reference_steps': s['features']['num_reference_steps']

    for s in complexity_data['samples']

# Load model metrics
metrics_df = pd.read_csv('metrics_results/MODEL_NAME/no_judge_metrics.csv')

metrics_df['complexity_score'] = metrics_df['sample_idx'].map(
    lambda x: complexity_map[x]['complexity_score']
)

)

### Key Indicators of Question Difficulty

**Quick Rules of Thumb:**

1. **Reference Steps (strongest indicator, r = +0.910)**
   - 1-3 steps → Easy
   - 4-7 steps → Medium
   - 8-15 steps → Hard
   - 16+ steps → Very Hard

2. **Question Length**
   - < 100 chars → Usually easy
   - 100-300 chars → Usually medium
   - 300-500 chars → Usually hard
   - > 500 chars → Very hard

3. **Question Type**
   - "Will these magnets attract/repel?" → Easy (yes/no)
   - "How many objects are red?" → Easy (counting)
   - "Why does this happen?" → Hard (explanation)
   - "What if we changed X to Y?" → Very hard (hypothetical)

4. **Answer Type**
   - Multiple choice (A/B/C/D) → Easier
   - Single number → Medium
   - Mathematical expression → Hard
   - Free text explanation → Very hard

5. **Linguistic Markers**
   - Has "if", "when" (conditional) → +Complexity
   - Has "because", "therefore" (causal) → +Complexity
   - Has "more", "less", "than" (comparison) → +Complexity
   - Multiple sentences → +Complexity

## FAQ

### Q: Why is my confidence low even though accuracy is high?

**A:** Confidence measures match certainty, not correctness.

Example:
- Correct answer via LLM judge: accuracy = 1.0, confidence = 0.85
- Correct exact match: accuracy = 1.0, confidence = 1.0

Low average confidence with high accuracy means many answers are correct but not exact matches (e.g., paraphrased).

### Q: Why is Precision > Recall (or vice versa)?

**A:** Imbalance indicates reasoning pattern:

**Precision > Recall:**
- Model generates few steps, most relevant
- Missing important reasoning steps
- **Fix:** Encourage more detailed reasoning

**Recall > Precision:**
- Model generates many steps, some irrelevant
- Verbose or redundant reasoning
- **Fix:** Encourage concise reasoning

### Q: Should I report std in papers?

**A:** YES! Always report std. It shows:
1. Scientific rigor
2. Transparency
3. Understanding of your data

Omitting std looks suspicious to reviewers.

### Q: How do I reduce variance?

**To reduce std:**
1. Remove placeholders (predictions for all samples)
2. Improve model consistency
3. Report by difficulty tier (std will be lower within tiers)

**BUT:** High std from task diversity is EXPECTED and GOOD!

### Q: Can I tag questions as complex without bias?

**A:** YES! Use feature-based complexity (Method 2):
- Reference step count
- Question length
- Linguistic features
- **NO model predictions**

This is unbiased and model-agnostic.

## Summary

**Key Takeaways:**

1. **Accuracy** measures final answer correctness
2. **Match F1** measures reasoning quality
3. **High std** is NORMAL for diverse datasets
4. **Confidence** shows match certainty, not correctness
5. **Report complexity** to explain variance
6. **Use feature-based complexity** to avoid model bias
7. **Always report std** with proper context
